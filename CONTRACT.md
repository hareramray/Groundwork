# Internal integration contract

Backend package: `grounding/`. Run from repository root. All coordinates normalized xyxy / xy. Runtime root `GROUNDING_DATA_DIR` environment variable or repository `data/`.

`grounding.storage`: `ROOT: Path`, `init_db()`, `put(kind,id,data)->dict`, `get(kind,id)->dict` (KeyError missing), `list_items(kind)->list[dict]`, `delete(kind,id)`, `uid()->str`, `now()->str`. SQLite JSON documents. put persists a complete document, no implicit merging. Kinds: image, version, run, evaluation, settings. Paths beneath ROOT: images/, versions/, runs/, exports/. `grounding.dataset.load_version(id)` returns manifest with records; record image_path is ROOT-relative. `grounding.dataset.verify_version(id)` validates hashes and returns same manifest.

Image JSON: `{id,filename,width,height,url,group,status,synthetic,elements:[],examples:[]}`. Elements `{id,class_id,label,bbox:[x1,y1,x2,y2],click_point:[x,y]}`. Examples `{id,instruction,target_present,element_id:null|string,status:'draft'|'reviewed'|'excluded',ambiguous:boolean}`. image.status computed unannotated/draft/reviewed/excluded; images never reviewed automatically. Initial classes `[button,textbox,link,checkbox,dropdown,icon]`.

Snapshot manifest `{id,name,created_at,classes,seed,group_by,records,stats,fingerprint}`. Records `{id,image_id,image_path,width,height,instruction,target_present,class_id,bbox,click_point,status,ambiguous,group,dataset_version,split:'train'|'val'|'test'}`. Only reviewed nonambiguous examples enter snapshot. Whole screenshot and same nonempty group remain one split. Split assignment immutable. images copied into versions/ID/images. Snapshot fingerprint/hashes validated before run/resume.

Training module exports `default_config()->dict`, `create_run(payload)->dict`, `launch_run(id)->dict`, `control_run(id,action)->dict`, `list_checkpoints(id)->list[dict]`, `export_model(run_id,checkpoint='latest')->dict`, `recover_runs()`. New run payload `{name,version_id,mode:'fresh'|'retrain',parent_run_id?,source_checkpoint?:'latest'|'best'|filename,source_export_id?,config:{...}}`. config defaults keys `image_size,batch_size,epochs,learning_rate,seed,grad_accum,width,text_dim,max_tokens,device,mixed_precision,checkpoint_every`. Run `{id,name,version_id,mode,parent_run_id,source_checkpoint,config,status,created_at,progress:{epoch,global_step,loss,losses,validation,learning_rate,elapsed_seconds,step_seconds,gpu_memory_mb,checkpoint},error,latest_checkpoint,best_checkpoint}`. New run creation validates, launch starts subprocess. Status queued/running/paused/stopped/completed/error/interrupted. Actions pause/stop/resume. Latest resumes same config and dataset; stopped resumes allowed. worker CLI `python -m grounding.training --run ID`. SQLite worker polling for control; do not overwrite requested control inadvertently. Agent owns all training/model/inference files.

Inference module exports `predict(run_id,checkpoint,image_path,instruction,threshold=0.5)->dict`, `evaluate(run_id,checkpoint,version_id,split='test',threshold=0.5)->dict`. Prediction `{target_present,presence_score,class_id,class_name,bbox,click_point,bbox_pixels,click_point_pixels,width,height,latency_ms,memory_mb,instruction,...}`. When abstaining public bbox and click are null; may include raw_bbox separately. Evaluation `{id,run_id,checkpoint,version_id,split,metrics,baselines,examples:[{...record,prediction,success,iou,image_url}],created_at}` persisted under evaluation kind by API. Inference export has ID and path in ROOT/exports. Predict/eval run synchronously in FastAPI sync routes (threadpool); training separately.

HTTP API base `/api`; errors JSON `{detail:string|object}`:
- GET /health; GET /dashboard => `{images,examples,reviewed,versions,runs,gpu}` numeric counters except gpu object/string.
- GET /classes => `{classes:[...]}`; PUT /classes same body.
- GET /images => image[]; POST /images multipart `files` => image[]; GET /images/{id}; PUT /images/{id} body `{elements,examples,group}` => image; DELETE /images/{id}.
- POST /synthetic `{count:24,seed:42}` => `{images,examples}` numeric generated counts. Draft synthetic annotations require explicit review; optional payload reviewed true only from explicit UI action.
- POST /datasets/validate `{group_by:'group'|'image',seed:42}` => `{errors:[],warnings:[],stats:{...}}`.
- GET /versions => manifests without records; POST /versions `{name,seed,group_by,train_ratio:0.7,val_ratio:0.15}` => manifest summary; GET /versions/{id} manifest.
- GET /versions/{id}/export => ZIP JSONL + images + manifest. POST /datasets/import multipart `file` ZIP => report counts. JSONL format documented in docs.
- GET /training/defaults => config; GET /runs => run[]; POST /runs payload => starts run; GET /runs/{id}; POST /runs/{id}/{pause|resume|stop}; GET /runs/{id}/checkpoints; POST /runs/{id}/export `{checkpoint:'latest'}` => export info incl download_url; GET /exports; GET /exports/{id}/download.
- POST /predict multipart `file,instruction,run_id,checkpoint,threshold` => prediction (also `image_id,image_url` stored upload). POST /predictions/correct `{image_id,instruction,class_id,bbox,click_point,target_present}` => draft example / image (open annotation editor to review).
- POST /evaluate `{run_id,checkpoint,version_id,split,threshold}`; GET /evaluations; GET /evaluations/{id}.
- GET /files/{path:path} image restricted beneath ROOT (only image files), snapshots use image_url `/api/files/<image_path>`.

Frontend React/TS Vite in frontend/, API proxy localhost:8000, build served by FastAPI at /. Dependency versions pinned + lock. Annotation SVG viewBox original dimensions with normalized state supports pointer draw/move/resize/clickpoint, zoom/pan. UI no fictitious metrics. Use API contracts, allow API adjustments via coordination.

Chat training teaches the same `ml.Grounder` selected from an existing grounding checkpoint. `grounding.chat` owns text examples, immutable teaching runs, workers, checkpoints, and generation. The combined architecture `cnn-gru-grounding-chat-v2` reuses `text_encoder` and adds `chat_embedding`, `chat_decoder`, and `chat_output`; chat training freezes original grounding weights. Checkpoints use kind `grounding_chat_training_checkpoint`, with grounding `config`, word `tokenizer`, `classes`, plus `chat_tokenizer` and `chat_training_config`. Storage kinds `chat_example`/`chat_run` record teaching history; artifacts live under `ROOT/chat/runs/`. Combined inference exports use standard `inference_export` kind, appear in the export library, and support both tasks in `FileGrounder`. Chat and grounding share one active training-worker limit.

Chat HTTP API:
- GET/POST `/api/chat/examples`; PUT/DELETE `/api/chat/examples/{id}`. Write body `{prompt,response}`; both nonempty after trimming, at most 500 characters. Example `{id,prompt,response,created_at,updated_at}`.
- GET `/api/chat/training/defaults` returns `{epochs,batch_size,learning_rate,device,seed}`.
- GET `/api/chat/sources` lists saved grounding and combined sources `{id,name,kind:'grounding'|'chat',status,latest_checkpoint,capabilities}`.
- GET/POST `/api/chat/runs`; POST body `{name,config,source_run_id?|source_chat_run_id?,source_checkpoint:'latest'}` requires exactly one source, copies its weights, and snapshots saved examples. GET `/api/chat/runs/{id}` returns run `{id,name,config,grounding_config,source_run_id,source_chat_run_id,source_checkpoint,capabilities,status,created_at,example_count,progress:{epoch,global_step,loss,elapsed_seconds},error,latest_checkpoint,...}`. Run config is chat settings; checkpoint config is grounding settings.
- POST `/api/chat/runs/{id}/stop` or `/resume`; stopping saves progress, resuming uses original examples/settings.
- POST `/api/chat/predict` body `{run_id,message}` returns `{reply,run_id,checkpoint,unknown_characters,...}`. Each message is independent. Requires a checkpoint containing learned updates.
- GET `/api/chat/runs/{id}/download` returns one `.pt` inference export containing both grounding and chat. `/api/predict` accepts unified chat run IDs using the latest checkpoint, and both original grounding models and combined models load in the browser CLI.
